端侧个人知识库与 seekdb 混合检索指南

为什么要在浏览器本地向量化

个人知识库经常包含学习笔记、项目文档和尚未公开的资料。浏览器本地向量化让原文不需要上传到云端推理服务，用户可以直接在自己的设备上完成文档编码。Transformers.js 能加载公开的开源 ONNX embedding 模型，ONNX Runtime Web 则提供 WebGPU 和 WASM 推理后端。模型文件可以从 Hugging Face 下载并缓存，但模型下载不等于云端推理：真正的矩阵计算仍发生在用户设备。

LocalBase 使用 all-MiniLM-L6-v2 生成 384 维向量。它体积较小，适合端侧运行，并能为英文语义检索提供稳定的句子表示。中文语料也能完成基础语义匹配，但如果需要更高质量的中文检索，可以替换为经过中文训练的同维度模型，并同步调整集合配置。所有向量在写入前经过均值池化与 L2 归一化，方便 seekdb 使用余弦距离计算相似度。

什么是混合检索

全文检索擅长精确关键词、产品名称、函数名和编号，向量检索擅长发现表达不同但含义相近的内容。只使用关键词时，用户查询“语义匹配”可能无法召回写着“向量相似度”的段落；只使用向量时，seekdb、refresh_index 等专有名词又可能不够精确。混合检索同时利用两种能力，因此更适合个人知识库。

LocalBase 不会在浏览器中分别获取两路结果再自行拼合。查询向量和查询文本一起发送到本地 Node 服务，seekdb-js 调用 collection.hybridSearch，数据库内部生成全文候选与 KNN 向量候选，最后使用 RRF，也就是倒数排名融合完成统一排序。RRF 不依赖两路分数是否处于同一量纲，而是根据文档在各路结果中的名次计算融合得分。

WebGPU 与 WASM 降级

WebGPU 能利用设备 GPU 加速 transformer 推理，通常是端侧模型的首选。应用通过 navigator.gpu 和 requestAdapter 检查可用性，并显式设置 device 为 webgpu。如果浏览器不支持 WebGPU、没有可用适配器，或模型初始化失败，应用会重新创建 Worker 并切换到 WASM。界面中的后端标签会显示 WebGPU 或 WASM，因此测试者可以明确验证降级路径，而不是根据速度猜测。

Worker 让模型推理不阻塞页面交互。文档按批次送入同一个已经加载的模型，避免每段文本都重新初始化运行时。批大小可以在 4、8、16 和 32 之间调整。较大的批次通常减少调度开销，但也会增加瞬时内存占用；比较性能时必须保持模型、精度、后端、语料和批大小等条件一致。

FP16、INT8 量化与检索质量

FP16 用半精度浮点表示权重，INT8 则用更紧凑的整数表示权重，两者都能减少模型下载体积和内存占用。LocalBase 的自动模式在支持 shader-f16 的 WebGPU 设备上使用 model_fp16.onnx，在 WASM 降级路径使用 model_quantized.onnx，FP32 基线使用 model.onnx。三种模型来自同一个公开仓库和同一个固定 commit，向量维度保持一致，下载脚本逐个验证 SHA-256。压缩比按实际 ONNX 文件大小计算，而不是根据理论位宽直接推算。

模型变小不代表检索质量一定不变。评测应固定同一组文档、查询和相关性标注，分别对 FP32、FP16 与 INT8 建库，再比较 Recall@K 和 nDCG@K。Recall@K 衡量相关文档有多少进入前 K 个结果，nDCG@K 还关注相关文档是否排在更靠前的位置。报告多次测量的原始记录和中位数，比只展示一次最快结果更可靠。

增量写入与索引刷新

每个文件先计算 SHA-256 内容摘要，文档 ID 由摘要与分块序号组成。相同文件再次导入时，应用先向 seekdb 查询已有 ID，已经存在的内容会跳过，不再重复执行 embedding。新增内容按批写入，所有批次完成后统一调用 refresh_index，而不是每个分块都刷新一次索引。这既减少索引维护开销，也能保证刷新完成后新增内容进入检索流程。

知识库对应独立的 seekdb collection。切换集合时，查询请求始终携带当前集合名称，旧查询的序号会失效，避免较晚返回的结果覆盖新集合页面。集合、文档原文、向量和来源元数据均持久化在 seekdb 中；浏览器 localStorage 只保存界面选择和测试记录，不承担文档存储或检索。

如何测量端到端性能

完整导入流程可以拆成文本读取与分块、模型加载、文档向量化、数据库写入、索引刷新几个阶段。查询流程则分别测量查询向量化、seekdb hybridSearch 和用户提交查询到结果可展示的总延迟。首次请求包含模型下载、初始化与预热，后续请求使用已经加载的模型，两者必须分开报告。

公平的优化对比需要固定设备、浏览器版本、数据规模和 seekdb 配置。测试可以重复五轮，保留每轮原始数据并计算中位数。若比较批处理优化，只改变批大小；若比较量化，只改变模型精度；若比较后端，只改变 WebGPU 与 WASM。性能提升不能以牺牲功能完整性或明显降低 Recall@K、nDCG@K 为代价。
