# 周边探索 Skill

## 名称
周边去哪儿：地点推荐助手

## 用途与适用场景
帮助用户根据当前位置和自然语言需求（如"找咖啡馆，步行不超过15分钟"），查询附近合适的地点，筛选后给出推荐列表，包含名称、地址、步行距离与预计时间、一句话推荐理由。

## 输入
用户提供：
- 起点坐标（纬度 + 经度），由评测平台提供，无需设备定位
- 城市名称或地点类型（如"杭州市"、"咖啡馆"）
- 自然语言需求（如"步行不超过15分钟，优先近一点的，推荐最多3家"）

## 输出
最多 3 条推荐，每条包含：地点名称、地址、步行距离（米）、预计步行时间（分钟）、推荐理由。附结果不足或查询异常的说明。

## 执行步骤

### Step 1：理解用户需求
从用户输入中提取：
- 地点类型关键词（如"咖啡馆"→"咖啡店"、"餐厅"→"饭馆"、"公园"→"公园"）
- 步行时间上限（分钟）→ 换算为步行距离上限（米）：1 分钟 ≈ 80 米
- 推荐数量上限（默认 3）
- 排序偏好（如"优先近"→按步行距离升序）
- 筛选条件（营业状态、价格区间等，若有）

### Step 2：调用高德地点搜索
使用高德 MCP Server 的 **地点搜索（around_search）** 能力：

```
around_search(
  location: "<经度>,<纬度>",   // 起点坐标
  radius: <搜索半径(米)>,      // = 步行时间上限(分钟) × 80 + 200 米缓冲
  types: "<地点类型代码>",      // 高德 POI 分类代码，如 050000(餐饮服务)、060000(购物服务)、110000(交通服务)、141200(公园)
  keywords: "<用户关键词>",     // 如 "咖啡"、"星巴克"
  offset: 20                   // 至少取 20 条候选，后续筛选
)
```

地点类型代码映射：
- 咖啡馆 / 咖啡店 / 咖啡 → `050000` + keyword 过滤
- 餐厅 / 吃饭 / 饭馆 → `050000`
- 公园 / 散步 / 绿道 → `141200`
- 超市 / 便利店 / 购物 → `060000`
- 电影院 / 看电影 → `080100`
- 书店 / 买书 / 图书馆 → `060400` 或 `040200`

### Step 3：调用高德步行路线规划
对 Step 2 返回的每个候选地点，使用高德 MCP Server 的 **步行路线规划（walking_direction）** 能力查询从起点到该地点的步行信息：

```
walking_direction(
  origin: "<起点经度>,<起点纬度>",
  destination: "<候选地点经度>,<候选地点纬度>"
)
```

从返回结果中提取：
- `distance` → 步行距离（米）
- `duration` → 预计步行时间（秒，换算为分钟）

### Step 4：筛选与排序
1. **硬过滤**：剔除步行时间 > 用户上限的候选
2. **去重**：同一点址（相同 location）只保留一条
3. **排序**：按步行时间升序（默认）或按用户偏好排序
4. **截断**：取前 N 条（N = 用户指定数量，默认 3）

### Step 5：生成推荐理由
为每条推荐生成 1 句理由，基于数据特征：
- "步行 5 分钟可达"
- "距离最近"
- "营业中（若 API 返回）"
- "评分 4.8（若 API 返回）"

不编造高德未返回的信息（如安静程度、排队情况），标注"未核实"。

### Step 6：输出结果
使用 Markdown 列表或表格呈现：

```
🎯 为您推荐以下 <N> 个候选地点：

1. **<地点名称>**
   - 📍 地址：<详细地址>
   - 🚶 步行：<距离> 米，约 <时间> 分钟
   - 💡 <推荐理由>

2. **...**

共检索到 <M> 个候选，筛选后满足条件 <N> 个。
```

### Step 7：异常处理
- **结果不足**：如实说明"在 <时间上限> 步行范围内仅找到 <实际数量> 个符合条件的地点，建议放宽条件（如增加步行时间上限或地点类型）"
- **查询失败**：说明"高德地点搜索服务暂不可用，请稍后重试"
- **路线查询失败**：该候选降级为"直线距离 <X> 米"，不列入推荐

## 约束
- 步行时间必须来自 walking_direction 路线查询，不能用直线距离替代
- 不编造地点、地址、距离或步行时间
- 对高德未返回的信息标注"未核实"
- 推荐数量上限不超过 3
